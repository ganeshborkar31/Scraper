# Architecture

FastAPI validates and persists requests; Celery workers perform source access. SQLAlchemy models separate canonical businesses from source observations and retain attribution, selected raw field values, and match decisions without storing whole provider responses. Connectors implement the common `Connector` contract (`validate`, `health_check`, `collect`) and return Pydantic-validated candidates plus observable record issues. The registered sources are the local dataset and bounded OpenStreetMap Overpass; `FixtureConnector` is in-memory and test-only. Normalization produces matching keys for names, domains, addresses, phones, and coordinates. Exact identifiers and exact branch evidence can reuse a canonical record; likely/uncertain candidates are recorded and remain separate. Administrators can explicitly merge and reverse a merge through audited endpoints. Connector-specific errors are recorded against their source in job outcomes, and one source failure does not discard other sources' results.

PostgreSQL is the intended deployed store, Redis carries jobs, and Celery Beat checks persisted schedules once per minute. No global crawling or arbitrary user URL fetching is implemented. Admin routes use HTTP Basic and should be served over TLS.
