# Architecture

FastAPI validates and persists requests; Celery workers perform source access. SQLAlchemy models separate canonical businesses from provider/source records and retain attribution metadata without raw payloads. Connectors implement the common `Connector` contract (`validate`, `health_check`, `collect`) and return a `ConnectorBatch` of Pydantic-validated `Candidate` values plus observable record issues. `BaseConnector` provides separate discovery, fetch, parse, normalization, pagination, and configured request-spacing hooks. A connector owns its transport: API adapters may use documented API pagination and authentication, while a website adapter may discover and parse approved pages. Neither mechanism is imposed on the other. `DatasetConnector` reads only configured local CSV/JSON files; `FixtureConnector` is in-memory and test-only. Connector-specific errors are recorded against their source in job outcomes, and one source failure does not discard other sources' results. Domain match (country scoped) precedes exact normalized name plus city matching.

PostgreSQL is the intended deployed store, Redis carries jobs, and Celery Beat checks persisted schedules once per minute. No global crawling or arbitrary user URL fetching is implemented. Admin routes use HTTP Basic and should be served over TLS.
